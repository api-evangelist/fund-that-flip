# Fund That Flip (Upright)

> Fund That Flip is a real estate fintech founded in 2014 that lends to residential redevelopers
> and offers passive income to accredited investors, having originated more than $2.6B in
> short-term hard money, fix-and-flip, new construction and DSCR loans. It acquired FlipperForce
> in 2022 and, in September 2023, the combined lending and software business rebranded as
> **Upright** (upright.us). The developer surface is the **FlipperForce Public API**.

Generated by the API Evangelist enrichment pipeline on 2026-08-16 from the provider's own
published OpenAPI document and public pages. The provider does not publish an llms.txt of its own.

## API at a glance

- Name: FlipperForce Public API
- Specification: OpenAPI 3.1.0, document version 0.0.10 (2026-07-25)
- Base URL: https://tools.flipperforce.com/api/v1
- Reference: https://tools.flipperforce.com/docs/api
- Machine-readable spec: https://tools.flipperforce.com/docs/api.json
- 37 paths, 50 operations, 52 component schemas, 15 tags
- Auth: HTTP Bearer. `Authorization: Bearer <api-key>`, key sent verbatim.
- Access: by request only — a workspace owner requests a key at
  https://tools.flipperforce.com/integrations (Workspace Settings > Integrations)
- Support: support@flipperforce.com

## Capability surface

- Projects — create, list, update, delete. The root aggregate for one property.
- Project expenses — transactions, line items, categories.
- Project income — create, list, show, update, delete.
- Project receipts — create, list, update, delete.
- Project photo log — list (date-grouped), create (EXIF-ordered via `photo_timestamp`), update, delete.
- Project updates — dated progress posts, with their own attached photos.
- Companies and company categories — workspace-level vendor reference data.
- Expense accounts — workspace-level chart-of-accounts reference data.
- Workspace activity log — audit trail with a filter-discovery endpoint (added v0.0.10).
- Attachment upload intent — two-step upload; `upload_type` is required.
- User account — confirm the key and resolve its workspace.

## Conventions

- Identifiers: bare UUIDs, no type prefix. References are `<entity>_uuid`.
- Timestamps: ISO 8601 Zulu with microseconds (`2025-04-30T21:21:10.123456Z`) since v0.0.9.
- Pagination: cursor-based — `cursor` and `per_page`.
- Filtering: repeated bracket arrays (`project_uuids[]`) plus range operators (`date[gte]`,
  `performed_at[lt]`) and boolean presence flags (`has_receipt`).
- Sorting: `sort=updated` (default) or `sort=nearby` with `latitude`/`longitude`.
- Errors: `application/json` `{"message": ...}`; 422 adds an `errors` object mapping each failing
  field to an array of reasons. This is NOT RFC 9457 problem+json.
- Tracing: every response carries an `x-app-invocation-id` header.
- Versioning: URL pinned at `/v1`; the contract moves through 0.0.x, and breaking changes have
  shipped inside v1.

## Known limitations (verified, not inferred)

- No idempotency key of any kind. Retried POSTs create duplicates.
- Rate limiting exists and returns 429, but no limit number, window, or `RateLimit-*`/`Retry-After`
  header is published or observed.
- No webhooks, events, or streaming surface; no AsyncAPI.
- No official SDK in any public package registry; no CLI.
- No MCP server and no A2A agent card.
- No `/.well-known/` documents on any host (security.txt, openid-configuration, agent card all 404).
- No status page, no deprecation policy, no published SLA.
